# Contributing

Спасибо за вклад в проект.

## Workflow

1. Создайте или выберите GitHub Issue.
2. Уточните требования и критерии приёмки до начала реализации.
3. Создайте отдельную ветку от `master`.
4. Вносите только изменения, относящиеся к задаче.
5. Выполните каноническую проверку:

```bash
docker compose run --rm app check
```

6. Создайте Pull Request со ссылкой на Issue.

## Development principles

- Следуйте существующей архитектуре и спецификациям.
- Предпочитайте небольшие, независимые изменения.
- Не дублируйте бизнес-логику и инфраструктурные правила.
- Не изменяйте публичные контракты без явной необходимости.
- Добавляйте или обновляйте тесты при изменении поведения.
- Разработка должна оставаться одинаково доступной людям и AI-агентам.

## Commits

Используйте короткие сообщения в imperative style:

```text
Add event publishing workflow
Fix calendar event validation
Update contributor documentation
```

## Pull Requests

PR должен:

- решать одну понятную задачу;
- ссылаться на соответствующий Issue;
- кратко описывать сделанные изменения;
- проходить `docker compose run --rm app check`;
- не содержать несвязанных изменений.

## Definition of Done

Изменение считается готовым, когда требования Issue выполнены, документация и тесты актуальны, а каноническая проверка проходит успешно.
